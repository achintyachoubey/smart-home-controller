# OOP Concepts: Where to Find Them

Every row names the exact file, class and method(s) where the concept is used, and
explains in plain words why it is used there. All paths are under `src/com/smarthome/`
unless they start with `test/`.

| Concept | Where (file → class → member) | Why it is used here (what to say in the viva) |
|---|---|---|
| **Classes & objects** | `model/Room.java` → `Room`; objects created in `service/DemoData.java` → `buildLivingRoom()` (`new Room("Living Room")`, `new Light(...)`) and in `Main.java` → `addDevice()` / `createDevice()` | A class is the blueprint (what every room has: a name and up to 10 devices); each `new` creates a separate object with its own data, so "Living Room" and "Bedroom" are two independent `Room` objects. |
| **Constructors: default (no-arg)** | `service/EnergyCalculator.java` → `EnergyCalculator()`; `service/FileManager.java` → `FileManager()` | They let us create a ready-to-use object without arguments: the calculator starts at Rs. 8.00 per kWh and the file manager uses the `data` folder. |
| **Constructors: parameterized** | `model/Light.java` → `Light(String name, double rating, int brightness, String colour)`; same pattern in `Fan`, `AirConditioner`, `SmartTV`, `DoorLock` | The caller sets every field at creation time, and the constructor validates each value, so an object can never start in an invalid state. |
| **Constructors: `this(...)` chaining** | `model/Light.java` → `Light(String name)` calls `this(name, DEFAULT_RATING, DEFAULT_BRIGHTNESS, DEFAULT_COLOUR)`; also `Fan(String)`, `AirConditioner(String)`, `SmartTV(String)`, `DoorLock(String)`, `FileManager()` | The short constructor reuses the full one instead of repeating its code, so the validation is written only once. |
| **Constructors: `super(...)`** | `model/Light.java` → `Light(String, double, int, String)` calls `super(ID_PREFIX, name, rating)`; the loading constructor `Light(String id, ...)` calls `super(id, name, isOn, rating)`; `exception/InvalidInputException.java` → `super(message)` | The parent class `Device` sets up the shared fields (ID, name, power); the child only adds its own fields. Exceptions pass their message up to `Exception`. |
| **Constructor overloading** | `model/Device.java` → two `protected Device(...)` constructors (new device vs. loaded from file); each device has three constructors | A brand-new device needs a fresh ID from `IdGenerator`, while a device read from `home_state.txt` must keep its saved ID; same name, different parameter lists. |
| **Encapsulation** | `model/Device.java` → all fields `private`, validated `setName()` / `setPowerRatingWatts()`; `model/DoorLock.java` → `pin` has **no getter**, only `unlock(int)` and `changePin(int, int)`; `model/Room.java` → `getDevices()` returns a copy | Data can only change through methods that check it, so a brightness of 150 or a name containing `\|` is refused. The PIN cannot be read at all, and nobody outside `Room` can corrupt its internal array. |
| **Inheritance** | `model/Light.java`, `Fan.java`, `AirConditioner.java`, `SmartTV.java`, `DoorLock.java` → `extends Device`; `exception/*.java` → `extends Exception`; `util/InputHelper.java` → `InputClosedException extends RuntimeException` | The ID, name, on/off and power logic is written once in `Device` and reused by all five device types ("a Fan **is a** Device"). |
| **Abstraction** | `model/Device.java` → `abstract class Device` with `abstract` methods `getDeviceType()`, `getStatus()`, `getCurrentPowerWatts()`, `toFileString()` | "A device" in general cannot exist, so `Device` cannot be instantiated; it only states *what* every device must be able to do, and each subclass decides *how*. |
| **Interface** | `model/Adjustable.java` → `interface Adjustable` (`setLevel`, `getLevel`, `getMinLevel`, `getMaxLevel`, `getLevelName`); implemented by `Light`, `Fan`, `AirConditioner`, `SmartTV`; used in `model/SceneAction.java` → `execute()` and `Main.java` → `buildControlOptions()` / `setLevel()`; also `test/.../TestRunner.java` → `ThrowingBlock` | Brightness, speed, temperature and volume are all "a level between min and max", so one interface lets the menu and scenes adjust any of them with the same code. `DoorLock` does **not** implement it because a lock has no level. |
| **Method overriding** | `model/Light.java` (and every other device) → `@Override getCurrentPowerWatts()`, `getStatus()`, `getDeviceType()`, `toFileString()`; `model/Device.java` → `@Override toString()` (overrides `Object`); `model/DoorLock.java` → `@Override turnOff()` | Each device calculates power differently (light uses brightness, fan uses speed, AC uses mode and temperature), so each subclass replaces the parent's method with its own version. |
| **Runtime polymorphism** | `model/Room.java` → `getTotalPowerWatts()` (`total += devices[i].getCurrentPowerWatts()`); `service/FileManager.java` → `saveHome()` (`d.toFileString()`); `Main.java` → `printRoomTable()` (`System.out.println(d)`); `model/SceneAction.java` → `execute()` (`adjustable.setLevel(value)`) | The variable's type is `Device` (or `Adjustable`), but Java decides **at run time** which subclass method to run, so one loop handles lights, fans, ACs, TVs and locks correctly. |
| **Method overloading** | `model/Room.java` → `findDevice(String id)` and `findDevice(int index)`; `service/EnergyCalculator.java` → `calculateKwh(Device, double)`, `calculateKwh(Room, double)`, `calculateKwh(Home, double)`, `calculateCost(double)`, `calculateCost(double, double)`; `test/.../TestRunner.java` → two `assertEquals` | Same action, different input: the compiler picks the version by the parameter types, so callers use one easy-to-remember name. |
| **Arrays: add** | `model/Room.java` → `addDevice()` (`devices[deviceCount] = d; deviceCount++;` with a capacity check); `Home.addRoom()`, `Home.addScene()`, `Scene.addAction()` | Fixed-size arrays plus a separate count; the capacity check throws `CapacityExceededException` when the array is full. |
| **Arrays: search** | `model/Room.java` → `indexOf()` (linear search with `equalsIgnoreCase`); `Home.findRoomOfDevice()`, `Home.indexOfRoom()`, `util/IdGenerator.java` → `indexOfPrefix()` | A simple loop compares each element until it finds a match or returns -1 / throws "not found". |
| **Arrays: remove-with-shift** | `model/Room.java` → `removeDevice()`; `Home.removeRoom()`, `Home.removeScene()`, `Scene.removeAction()` | After removing an element every later element moves one place left, the last used slot is set to `null`, and the count goes down, so there are never gaps. |
| **Arrays: copy** | `model/Room.java` → `getDevices()`; `Home.getRooms()`, `Home.getScenes()`, `Scene.getActions()`, `Light.getColourOptions()`, `AirConditioner.getModeOptions()` | A new array trimmed to the real count is returned, so callers cannot change the object's private array. |
| **Arrays: other uses** | `util/IdGenerator.java` → parallel arrays `PREFIXES` / `COUNTERS`; `service/FileManager.java` → `readLastLogLines()` (circular buffer); `Main.java` → `buildControlOptions()` (parallel `labels` / `codes`) | Arrays replace collections everywhere; the circular buffer keeps only the last *n* log lines in memory. |
| **Operators: arithmetic** | `model/Light.java` → `getCurrentPowerWatts()` (`rating * brightness / 100.0`); `model/AirConditioner.java` → `getCurrentPowerWatts()`; `service/EnergyCalculator.java` → `calculateKwh()` (`watts * hours / 1000`) | These are the power and energy formulas from the specification. |
| **Operators: relational & logical** | `model/Light.java` → `checkBrightness()` (`value < MIN \|\| value > MAX`); `service/EnergyCalculator.java` → `monthlyKwh()` (`hoursPerDay >= 0 && hoursPerDay <= 24`); `Main.java` → `warnIfLockPoweredOff()` (`instanceof ... && !d.isOn()`) | Used for range validation and combined conditions. |
| **Operators: `!` (logical NOT)** | `model/Device.java` → `toggle()` (`isOn = !isOn;`) | Flips a boolean in one step: on becomes off and off becomes on. |
| **Operators: ternary `? :`** | `model/Device.java` → `toString()` (`isOn ? "ON" : "OFF"`); `model/DoorLock.java` → `getStatus()`; `Main.java` → `plural()` | A compact if-else that produces a value inside an expression. |
| **Operators: compound assignment** | `model/Room.java` → `getTotalPowerWatts()` (`total += ...`); `service/EnergyCalculator.java` → `calculateSlabBill()` (`bill += ...`); `model/DoorLock.java` → `getStatus()` (`status += ...`) | Adds to a running total without repeating the variable name. |
| **Operators: `++` / `--` and modulo `%`** | `model/Room.java` → `addDevice()` / `removeDevice()` (`deviceCount++`, `deviceCount--`); `Main.java` → `buildControlOptions()` (`codes[n++]`, post-increment inside an index); `service/FileManager.java` → `readLastLogLines()` (`buffer[total % n]`) | `++`/`--` keep the array counts right; `%` wraps the index round so the buffer reuses its oldest slot. |
| **Control flow: `while`** | `Main.java` → `manageRooms()`, `controlDevice()` (`while (true)` menu loops); `util/InputHelper.java` → `readInt()` (loop until valid); `service/FileManager.java` → `loadHome()` (`while ((line = reader.readLine()) != null)`); `Main.startup()` (`while (home == null)`) | Repeats until a condition changes: until the user picks "Back", types valid input, or the file ends. |
| **Control flow: `do-while`** | `Main.java` → `runMainMenu()` | The main menu must be shown **at least once** before checking whether to continue, which is exactly what a do-while does. |
| **Control flow: `for` / enhanced-`for`** | `model/Room.java` → `removeDevice()` (index `for` for shifting); `model/Home.java` → `getOnDeviceCount()` (`for (Device d : rooms[i].getDevices())`); `service/FileManager.java` → `saveHome()` | Index loops when the position matters (shifting); enhanced-for when every element is simply visited. |
| **Control flow: `switch`** | `Main.java` → `handleMainChoice()` (on `int`); `model/SceneAction.java` → `execute()` (on the enum `ActionType`); `model/AirConditioner.java` → `getCurrentPowerWatts()` and `service/FileManager.java` → `loadHome()` / `parseDevice()` (on `String`) | Classic `case ...: break;` picks one branch out of many fixed choices, which is clearer than a long if-else chain for menus and record types. |
| **Control flow: `if-else` chain** | `service/EnergyCalculator.java` → `calculateSlabBill()`; `Main.java` → `buildControlOptions()`, `editSceneSteps()` | Slabs are ranges (≤100, ≤300, ≤500, above), which a switch cannot test, so an if-else-if chain is used. |
| **Control flow: `break` / `continue` / `return`** | `break` in every `switch` (e.g. `Main.handleMainChoice()`); `continue` in `model/Room.java` → `turnAllOff()` (skip door locks) and `FileManager.loadHome()` (skip blank lines); early `return` in `Main.addDevice()` | `continue` skips the rest of one loop pass; `break` leaves a `switch`. |
| **Static members** | `util/IdGenerator.java` → `static` counters and `nextId()`; `model/Room.java` → `public static final int MAX_DEVICES`; `util/InputHelper.java` → `private static final Scanner SCANNER`; `Main.java` → `static Home home`; `service/DemoData.java` → `static buildDemoHome()` | Things that belong to the class, not to one object: there is only one ID sequence, one keyboard scanner and one set of limits for the whole program. |
| **`final` keyword** | `model/Device.java` → `private final String id`; `model/DoorLock.java` → `final class DoorLock`; constants such as `Light.DEFAULT_RATING` | An ID never changes once created; `DoorLock` is final because its constructor calls `turnOn()`, which is only safe if no subclass can override it. |
| **Enum** | `model/ActionType.java` → `enum ActionType { TURN_ON, TURN_OFF, TOGGLE, SET_LEVEL, LOCK }`; used in `SceneAction.execute()` (switch), `FileManager.parseActionType()` (`ActionType.valueOf`), `Main.chooseActionFor()` (`ActionType.values()`) | A fixed set of named constants: a misspelt action cannot compile, and an unknown action in a file is detected by `valueOf`. |
| **Exception handling: custom checked exceptions** | `exception/DeviceNotFoundException.java`, `CapacityExceededException.java`, `InvalidInputException.java` (each `extends Exception`); thrown in `model/Room.java` → `addDevice()`, `findDevice()`, and in every validating setter | Checked exceptions force the caller to handle "not found", "full" and "invalid value" situations, so they cannot be forgotten. |
| **Exception handling: try-catch** | `Main.java` → `addRoom()`, `renameDevice()`, `performControl()` (catch and show `e.getMessage()`); `util/InputHelper.java` → `parseIntInRange()` (catches `NumberFormatException`) | Errors are caught at the user-interface layer and shown as a friendly message; the program never prints a stack trace. |
| **Exception handling: multi-catch** | `model/Scene.java` → `run()` (`catch (DeviceNotFoundException \| InvalidInputException e)`); `service/FileManager.java` → `loadHome()`; `Main.java` → `addDevice()` | One handler for several exception types that are dealt with the same way. In `Scene.run()` it is inside the loop, so one failing step never stops the remaining steps. |
| **Exception handling: try-with-resources** (used instead of `finally`) | `service/FileManager.java` → `saveHome()`, `saveScenes()`, `loadHome()`, `loadScenes()`, `appendLog()`, `readLastLogLines()` | The file is closed automatically even if an exception happens, which is what a `finally { close(); }` block would otherwise do. (`finally` itself is not used.) |
| **Exception handling: rethrow and unchecked exceptions** | `Main.java` → `controlLock()` (catch, log "PIN change refused", `throw e`); `Main.runMainMenu()` (catches `RuntimeException` → "Unexpected error"); `util/InputHelper.java` → `InputClosedException` caught in `Main.main()`; `service/EnergyCalculator.java` → `IllegalArgumentException` | Logging and then passing an error on; an unchecked signal for end of input lets `main()` save and exit cleanly from any depth. |
| **File handling: write** | `service/FileManager.java` → `saveHome()`, `saveScenes()` (`BufferedWriter` over `FileWriter`, overwrite) | Saves the whole state as readable pipe-separated text so it can be restored next time. |
| **File handling: read** | `service/FileManager.java` → `loadHome()`, `loadScenes()`, `readLastLogLines()` (`BufferedReader` over `FileReader`, `String.split`) | Rebuilds the objects line by line, skipping corrupt lines with a warning. |
| **File handling: append** | `service/FileManager.java` → `appendLog()` (`new FileWriter(file, true)`) | `true` means "add to the end" so the activity log keeps its history across runs. |
| **Packages** | `com.smarthome` (`Main`), `com.smarthome.model`, `com.smarthome.service`, `com.smarthome.util`, `com.smarthome.exception`; `import` statements at the top of every file; `protected` members such as `Device.baseFileString()` | Related classes are grouped (data model, services, utilities, errors), names cannot clash, and access modifiers control what other packages may use. |
